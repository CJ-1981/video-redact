## Why (ADR summaries — full register in design.md §6)

- **ADR-1** Dev ES modules + `tools/inline.mjs` → single `dist/index.html`, instead of pure inline-only source (untestable by vitest) or a full bundler (heavier than needed).
- **ADR-2** mediabunny for all container work, instead of mp4box.js + muxer glue (demux-only, .mov flaky) or ffmpeg.wasm (no HW accel, memory ceiling).
- **ADR-3** Track keyframes keyed in seconds, not frame indices (frame keys break under VFR; sink timestamps are authoritative).
- **ADR-4** `<video>`-element playback for review, instead of CanvasSink re-decode (CPU cost, scrubbing complexity).
- **ADR-5** WebGPU EP only off WebKit (ort#26827 blowup on WebKit); WASM directly on Safari; WebGL EP rejected (deprecated).
- **ADR-6** Pixelate-only redaction: gaussian silently no-ops on Safari < 18 (a redaction failure), solid destroys context — user decision, safety-aligned.
- **ADR-7** Export avc/MP4 primary → avc software → vp9/WebM ladder; audio always packet-copied (no re-encode path: quality loss + AAC-encode gaps, e.g. Linux Chrome).
- **ADR-8** IndexedDB byte cache for models with `name@version` keys (30 MB re-download per session is unacceptable; Cache API gives less byte-level control).
- **ADR-9** Display-oriented (rotation-applied) coordinates everywhere after ingest — eliminates the portrait bug class at the boundary.

No upstream sha256 is published for either model — the pinned byte size is the only integrity gate (mismatch warns; ORT session creation rejects truly corrupt bytes). Cache: IndexedDB db `video-redact-models`, store `models`, key `${name}@${version}`; cache-first with deduped in-flight downloads.

## Build & versioning

`npm run build` → `tools/inline.mjs`: esbuild bundles `src/main.js` (ESM, no minify; `mediabunny`/`onnxruntime-web` stay external and resolve via the dist importmap), the dev `<script src>` tag is replaced with the inline bundle, `__APP_VERSION__` (from package.json) and `__BUILD_DATE__` (UTC date of build) are injected as literals, esbuild's per-module path comments are stripped, `</script>` is escaped, and the build FAILS if any `src/` reference leaks (single-file guarantee). Output: `dist/index.html` (~281 KiB — 287,706 bytes at v1.18.1). At runtime the version shows in the footer badge (`v1.18.1 · built <date>`) and console at boot; unbuilt dev mode shows `dev build (unbuilt)`.

## Design notes added since v1.0.0 (SPEC-VID-002 amendments + field fixes, v1.1.0–v1.18.1)

- **Detection threshold config (REQ-113)** — face/plate confidence gates are user-configurable (`settings.confFace`/`confPlate`, Analyze-panel sliders, defaults `DEFAULT_CONF_FACE` 0.60 / `DEFAULT_CONF_PLATE` 0.25). The values ride every `detectFace`/`detectPlate` call of the analyze loop (full-frame AND tile passes) via per-call `opts.confThreshold`; detector decode functions take the threshold as an option, so no baked constants remain in the loop.
- **Single-frame threshold compare (REQ-114)** — one decode + ONE inference per model: `analyze.sampleFrameAt()` decodes a single frame through the analyze loop's seam; `createDetectors()` additionally returns raw accessors `detectFaceRaw`/`detectPlateRaw` that skip decoding and hand back the undecoded model outputs; `decodeYunetOutputs`/`parsePlateRows` re-decode that single inference at each of the five fixed levels (0.15–0.75). `main.buildThresholdPanels` turns counts into panels; clicking a panel applies the level to both sliders (`applyThresholdLevel`). N inferences for N levels would be ~5× the cost — this design keeps it at one.
- **Manual region model (REQ-103/108/109)** — a manual track is a sparse-keyframe Track (single box) spanning the FULL video duration by default, source `'manual'`, style `'solid'`, colored from the same `TRACK_COLORS[(id − 1) % 8]` palette as auto tracks (distinct per track; identity signalled by the "Manual #N" label + dashed chip outline, not color). Trimming goes through one path: chip-edge drag (±6 px zones, ±14 px on coarse pointers) or per-row clock inputs (`parseClockInput`) both call `editor.trimTrack` (min span 0.1 s), so preview, chips, row readout and export span move together.
- **CLEAR transition (v1.6.0)** — `STEP_TRANSITIONS` gains `CLEAR: 'gate'` legal from EVERY step; DOM-side `clearAll()` aborts in-flight analyze/export (generation counter drops stale callbacks), destroys the editor (cancels preview frame loops), revokes the preview blob URL, unloads the `<video>` (`src` removed + `load()`), disposes the mediabunny `Input`, sweeps leftover OPFS export temps (`exports/redact-export-*` — the REQ-019 hygiene on explicit clear), and resets the file input (`fileInputNeedsReset`) so re-selecting the SAME file re-fires `change`. Panels reset from one `DEFAULT_SETTINGS()` factory. Model cache, stage height and version badge survive.
- **Mobile layout (REQ-112)** — single CSS breakpoint `@media (max-width: 820px)`: right rail stacks below the timeline, ≥ 40 px touch targets, 48 vh default stage, header/stepper compression. Coarse-pointer hit zones: `editor.effectiveEdgePx` widens chip-edge grab zones 6 px → 14 px (`CHIP_EDGE_PX_COARSE`) so fingertip trims work.
- **Overlay controls + idle auto-hide (REQ-111)** — fullscreen/zoom modes render an in-stage control bar (`.stage-overlay-controls`, distinct ov-* ids) calling the SAME shared transport actions as the bottom bar (`togglePlay`/`stepFrame`/`setSpeed`/`exitPreview`). It hides after `OVERLAY_HIDE_MS` (3000 ms) without pointer/touch activity on the stage and re-shows on activity or mode enter.
- **Scrub thumb (v1.7.0–v1.9.0)** — a 20 px round thumb (`#timeline-thumb`, `role="slider"`) rides the playhead and drags to scrub (pointer→time through `timelineTimeAt`, ~50 ms throttled seeks, exact endpoint seek on release). Reliability layers: window-level capture net mirrors move/up/cancel when pointer capture silently fails (v1.8.0), the release point is pinned until the endpoint seek lands (v1.8.0 condition pin replaced in v1.9.0 by a 350 ms time-boxed pin — `THUMB_PIN_MS`/`thumbPinSettled`) so the thumb can never freeze permanently, and playback following is carried by a `timeupdate`-driven `updatePlayhead` path (v1.8.1) for browsers whose rVFC frame loop never fires.
- **Keyboard gating + control focus (v1.6.1)** — doc-level keyboard shortcuts release focus on pointer-activated controls and exclude only typing surfaces (`shortcutEnabledFor`), so Space keeps toggling playback after clicking any control; since v1.10.0 Space is legal at READY (a live editor is mounted there), while `←`/`→` frame-step stays review/done-gated and export stays gated to review/done (`deriveStep('ready','EXPORT_START')` is null).
- **Mute (v1.8.0)** — `#mute-button` / `#ov-mute` route through `toggleMute()` flipping `video.muted` only (volume survives); `muteGlyph` + `aria-pressed` are driven by the `volumechange` event, so external mute flips stay in sync. New files load unmuted; `clearAll` resets to unmuted.
- **Runtime self-diagnostics (v1.8.2/1.9.0)** — `?debug=1` (`parseDebugFlag`) makes mountApp log one compact `[diag]` JSON line every 2 s for ≤10 min (`formatDiagLine`, `DIAG_KEY_ORDER`), leading with the running bundle identity (version + build date) then live transport facts (`tu` timeupdate ticks, `vfc` delivered-rVFC ticks, error/unhandledrejection counters, gesture state, thumb position) via a shared `globalThis.__VR_DIAG`. Without the flag there is no interval and zero overhead.
- **Editor exception isolation (v1.9.0) + mount-at-READY (v1.10.0)** — keyboard wiring runs before the editor mounts; every mount goes through `mountEditorSafe` (a throw becomes a readable toast + diag event, keyboard stays live) and per-tick exceptions cannot stop the draw loop. The editor mounts at READY through `mountEditorLive()` (file open, capability OK, 0 tracks) — timeline/scrub/keyboard/manual boxes work pre-analysis; analyze completion only sets the merged track state (`mergeManualTracks(existing, analyzed)`: keeps every `source==='manual'` track, appends analyzed tracks, re-assigns colliding auto ids) and calls `editor.refresh()` — no destroy/remount churn.
- **Keyboard transport + ergonomics wave (v1.11.0–v1.14.1, REQ-117..124)** — `←`/`→` jump ±5 s (`SEEK_STEP_S`, REQ-122) while `Shift+←/→` keeps the ±1-frame step; `F` toggles fullscreen/enlarge, `M` mute. Light theme (REQ-124) is a CSS custom-property swap persisted in `localStorage` (`video-redact-theme`, `loadTheme`/`saveTheme`/`nextTheme`/`themeGlyph`). File-info block above the capability report (`fileInfoRows`, REQ-119). Minimum-object-size button filter (`SIZE_FILTER_VALUES` 0/24/48/96, REQ-120). Analysis downscale (REQ-117: `DOWNSCALE_VALUES` full/1080p/720p/480p — 480p added in v1.18.0, `normalizeDownscale`, `analyze.scaleFactorFor` caps the analyze frame size and detections are rescaled to native display coords before tracking). Bulk restyle (`setAllTrackStyles`), collapsible panels, Models panel under the footer, compare + track list stacked below the timeline (REQ-116/123). Draggable rail (`clampRailWidth`/`nextRailWidth`/`dragRailWidth`, 240–480 px) and intake (`dragIntakeWidth`) handles with keyboard + double-click reset (REQ-118) — width changes kick a throttled editor redraw during the drag and an exact one on release so rVFC-dead machines keep an unstretched preview (v1.14.1; the `timeupdate` fallback re-draws ~4 Hz).
- **Trim regions + trimmed export (v1.15.0–v1.15.2, REQ-125/126)** — `main` owns `app.trims` (pure helpers `normalizeTrims`/`addTrim`/`moveTrimEdge`/`removeTrim`/`trimsAt`/`keptSegments`, min span 0.1 s); `editor.trimRegionViews` renders the greyed overlays with draggable ✂ edges. Analysis SKIPS frames inside trim regions (`analyze.inTrims` — no draw, no inference, no tracking; skipped count reported in analyze status), so large trims speed the pass up and ghost tracks never appear. Export excludes trims: one native mediabunny trim `Conversion` per kept segment (pixelation burn-in per segment, audio packet-copied), then encoded packets are concatenated into one file with continuous timestamps (no re-encode); no trims → the single-pass path is byte-for-byte unchanged. All segment temps are cleaned up after delivery.
- **Export resolution + audio removal (v1.16.0) and the choices-reset split (v1.17.1, REQ-127)** — `exporter.exportGeometry(resolution, w, h)` returns `{sf, outW, outH}` (locked-size burn-in prevents silent reversion to source dims); `scaleTracks` rescales every keyframe box by the same factor; encoder hints follow. "Include audio" off discards the audio track. v1.17.0 fixed the missing-element-refs regression; v1.17.1 fixed the deeper bug: the export click used to run `resetExportUi()` (which reset the selects) BEFORE the settings were read, so every export ran with defaults — choices now reset only on file load and Clear (`resetExportChoices` at both sites), and an export click reads the live UI. Verified with a real-browser probe (`tools/debug-export-settings.mjs`: 2560×1440 source → exactly 1280×720 with 0 audio tracks).
- **Pixelation strength (v1.17.0, REQ-129)** — `redact.PIXEL_STRENGTHS = {fine:1, normal:2, coarse:3, max:4}`; `pixelStrengthMultiplier(strength)` multiplies the block size (invalid/missing falls back to `normal` ×2, so preview and export — the shared `pixelateFrame` seam — always agree; `fine` ×1 preserves the pre-v1.17 block size). `main.normalizePixelStrength`/`pixelStrengthPressed` wire the button group.
- **Threshold compare honors settings (v1.17.0, REQ-128)** — the single-frame compare applies dashcam mode, minimum object size (`filterByMinSize`) and detection detail/downscale to the panels, so they show what a real analyze would find; `describeCompareContext` captions the active settings.
- **Project save/load (v1.17.0, REQ-130)** — `src/project.js`: `serializeProject` → `.vrproj` JSON (`PROJECT_FORMAT_VERSION = '1'`: settings incl. pixelStrength, trim regions, tracks incl. manual regions, video identity — no video bytes); `parseProject` validates version/structure (typed errors for corrupt/unsupported projects); `validateVideoMatch` compares name/size/date on re-association and surfaces readable warnings. Loading adopts tracks via `adoptTracks` + `clampTracksToDuration`; Clear wipes a loaded-but-unapplied project.
- **480p export resolution (v1.18.0)** — `480p` joins `DOWNSCALE_VALUES` (main.js) and the `analyze.DOWNSCALE_CAPS` table (long edge 854), so the export select, `normalizeDownscale` and `exportGeometry` all accept it with no new code path: the burn-in canvas, `scaleTracks` and the encoder hints scale by the same long-edge rule as 1080p/720p. It is also a legal analysis-downscale value.
- **Below-timeline layout inside the preview column (v1.18.0–v1.18.1)** — the `#below-timeline` section (Tracks panel, then Compare-thresholds) moved from a workspace-grid child INTO `#stage-column`, directly after `#timeline` (contract pinned by `tests/unit/mobile-ui.test.js`: it must sit after the timeline and before the `#rail-resize` handle, and the CSS must carry NO `grid-column`). Root cause fixed: a tall right rail pushed a grid-placed section down, leaving a large void after the timeline. It is now a plain block (`margin-top: 16px` + the column's 12px flex gap = a constant 28px gap at every layout width), and since v1.18.0 it also matches the preview-column width instead of spanning under the rail.

## Test strategy

- **Unit (vitest, node env)** — 15 files, 765 tests. Pure logic is tested directly (tracker, redact geometry + style dispatch + pixel strength, timeline model incl. trim/style/clock parsing + trim-region views, detector decode math + tile geometry, capability guidance, models cache, exporter ladder + geometry scaling + per-segment trims, analyze loop + sampleFrameAt + trim skipping + min-size filter, project serialize/parse/validate, main formatters/state machine incl. CLEAR + threshold panels + diag line + trims + project save/load, stage/rail/intake resize helpers, theme, mobile-UI breakpoint wiring, version stamp). Browser/CDN dependencies are seamed: duck-typed mediabunny inputs (capability), injectable WebCodecs/UA (capability), `setModelDeps` (fake-indexeddb + stubbed fetch), mocked `onnxruntime-web` import, injectable canvas factory/yield/clock (analyze). Coverage gate: ≥ 85% lines on the 8 logic modules (main.js/editor.js DOM wiring measured but gated via E2E).
- **E2E (Playwright, Chromium)** — 5 spec files, 6 tests, serial `workers: 1` with a shared worker-scoped context so the IndexedDB model cache and HTTP cache carry over (offline-models spec depends on that ordering). Specs: smoke (2), journey (in-page re-decode burn-in assertion + AAC preserved), auto-detect (real YuNet detection on `tests/fixtures/detectable.mp4`, provenance in `fixture.json`), offline-models, errors. Real network is used (CDN libs + model weights, ~40 MB first run — perf gate P-4).
- **Fixtures** — generated in-browser by `tools/make-fixture.mjs` using the same pinned mediabunny bundle.
- **Quality gate** — `npm run gate` = eslint + `tsc --noEmit` + vitest + build, all exit 0.
